# Assumptions Register: Scale with Agents

*Companion to [[beachhead-scale-with-agents]]. Each assumption below is what has to be true for this beachhead to work. Status values: untested / testing / validated / invalidated. Update after every discovery call or pilot data point — log the update in Customer Discovery Log and reference it here.*

## 1. Missing context is the principal cause of agent failure
- Status: untested
- Evidence so far: none yet
- Next test: ask directly in discovery calls what breaks — model quality, or missing rules/knowledge/permissions

## 2. The underlying workflow is sufficiently clear to automate
- Status: untested
- Evidence so far: none yet
- Next test: qualifying question — "Is the process itself well-defined and agreed on internally?" Disqualify if no.

## 3. One knowledge layer can serve several future agents
- Status: untested
- Evidence so far: none yet
- Next test: only testable after first pilot — ask if a second workflow can reuse the same context layer, and how much

## 4. Knowledge can remain current without a dedicated documentation team
- Status: untested
- Evidence so far: none yet
- Next test: during pilot, track how much manual upkeep the context layer needs

## 5. Agent performance creates measurable savings or additional capacity
- Status: untested
- Evidence so far: none yet
- Next test: the two-version pilot (see Cheap Test Protocol) — measure completion rate, correction time, escalation quality, time saved

## 6. The company will pay based on avoided hiring or increased service capacity
- Status: untested
- Evidence so far: none yet
- Next test: ask for payment for a second workflow before building out the platform

## Cross-cutting risk to watch
A knowledge layer cannot repair an undefined process. If people disagree about how work should be done, Rizom may be uncovering an operating-model problem rather than a documentation problem — this is a disqualifier, not a sales objection to push through.
