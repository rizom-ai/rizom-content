# Beachhead: Scale with Agents

*Selected as Rizom's initial beachhead market, agreed in team session with Jan Hein, Samantha, Joanna, and Nathalie. This is the canonical reference for the ICP, wedge, and disqualifiers — point here instead of re-explaining in Slack.*

## ICP

**Firmographic**
- B2B SaaS or knowledge-intensive service company
- 10–40 people
- €1M–€5M ARR
- Profitable or well-funded (not pre-revenue, not burning fast)

**Situational (the trigger)**
- Already running, or just finished, an AI agent experiment — customer support, onboarding, account research, product ops, or internal coordination
- Results are plausible but inconsistent: the agent sometimes works, sometimes doesn't, and nobody fully trusts it yet
- Leadership suspects the model isn't the problem — the agent lacks reliable context: rules, permissions, escalation paths, up-to-date knowledge

**Buyer**
- Founder/CEO, COO, or Head of Product/Ops who owns the "scale without proportional headcount" mandate

**Disqualifiers**
- No live or recent agent experiment (too early — nothing concrete to diagnose)
- Process itself is undefined or contested internally (a context layer won't fix a workflow nobody agrees on)
- Team wants a general-purpose "AI search" tool, not a production workflow improvement

## The wedge (positioning)

> Rizom turns scattered operating knowledge into a governed context layer, then uses it to make your first agent workflow reliable.

Not "organize your knowledge." **"Make one valuable agent safe and effective."**

The open question this beachhead tests: will customers pay for the knowledge layer once they see the agent work — or do they only value the agent itself? If the latter, Rizom risks being an automation consultancy, not a product. If the same layer improves multiple agents/workflows, there's a product.
